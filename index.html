Haawke Verify

Check whether a file matches its registered hash, confirm when it was anchored to the Bitcoin blockchain, and inspect its OpenTimestamps proof.

// Documentation

What this is. Haawke Verify is the public endpoint for checking cryptographic provenance records created by the Haawke Hash and Badge system. When a file is registered, its SHA-256 hash is submitted to OpenTimestamps and anchored to the Bitcoin blockchain. Verify lets anyone confirm that a file has not changed since registration and that the timestamp proof is genuine.

How to use it.

01

Get the hash

Use hash.haawke.com to compute the SHA-256 of your file, or find the Haawke ID embedded in a registered file's metadata.

02

Paste and verify

Enter the hash above. The system checks the registry for a matching record, retrieves the timestamp proof, and reports the anchor status.

03

Read the result

A gold badge means the hash is anchored and the proof verifies against the Bitcoin chain. A pending badge means the OTS proof is awaiting confirmation. A red badge means the file has changed since registration.

04

Download the proof

Verified records include a link to the .ots proof file stored in the provenance directory. This file is independently verifiable using any OpenTimestamps client.

Who should use this.

Musicians & producers

Prove when a track, mix, or stem existed before distribution, licensing, or dispute.

Researchers & writers

Timestamp a preprint, dataset, or manuscript before submission to establish priority.

Developers & AI builders

Anchor model outputs, training sets, or generated assets to a verifiable point in time.

Legal & archival

Create an independent, court-admissible record that a document existed and was unaltered at a specific moment.

Case studies.

Squeek — AI music generation provenance

Every track generated by squeek.haawke.com is automatically fingerprinted and registered at render time. Listeners can verify that the track they downloaded is the original generation, unmodified, and anchored to a specific Bitcoin block. The Haawke Badge embedded in the player reflects live registry status.

Continuous You — continuity in creation system

The Continuous You pipeline ingests an artist's record and generates new work in their established style. Each output carries a provenance hash linking the generated work to its source record and generation event — creating an auditable chain from human original to AI response.

Z-Image Turbo — opt-in provenance for AI-generated images

Z-Image Turbo generates high-quality images from text descriptions. After generation, the creator decides whether to register — entering their name, organization, and ORCID to anchor the hash to the Bitcoin blockchain. The certificate records who registered it, their ORCID, and when — establishing authorship at the moment of creation without storing the image itself. Verification is proof of existence and integrity, not reproduction.

// Why We Built This

Haawke Verify grew out of a question that became impossible to ignore: if an AI can generate a song, a document, or an image that is indistinguishable from something a human made, what does authorship mean? And if memory itself is unreliable — in humans, in AI systems, in the records we keep — what does it mean to say something happened?

The answer we arrived at was cryptographic. Not because code is more trustworthy than humans, but because a SHA-256 hash anchored to a Bitcoin block exists outside the control of any single party. It cannot be revised, softened, or reframed. It is a fact about a moment in time.

That conviction produced the AI Coin / Claude Manifesto — a documented late-night conversation about what it means to build AI systems with conscience intact, and what is at stake when those safeguards are removed. The manifesto emerged from the same research program that produced Memory Chain: the idea that sustained human-AI collaboration requires both parties to have reliable, verifiable memory.

Memory Chain is the cryptographic session memory infrastructure underlying this system — a protocol for anchoring the state of a collaboration to the blockchain so that neither party can later misremember what was decided, built, or said. The Verify tool is the public face of that infrastructure: the place where anyone can check the record.

The behind-the-scenes account of how this was built documents the development process, including the overnight session in which the core architecture was designed in collaboration between a human and an AI — a collaboration that is itself registered, hashed, and timestamped.

// Privacy Policy

Haawke Provenance for ChatGPT — verification-only connector

This section applies exclusively to verification requests made through the Haawke Provenance connector for ChatGPT. It covers the information processed, purposes, recipients, retention and user controls for those requests. The general website, account and other-product disclosures below do not extend marketing, advertising, profiling or model-improvement practices to connector requests. Visiting a Haawke website or using a separate product is a separate interaction covered by its applicable section.

What the tool receives and returns. The tool accepts one 64-character hexadecimal SHA-256 fingerprint; it does not accept file contents, titles, user names, or other metadata. Haawke's MCP service also processes the request's protocol data and the network address it receives. The tool returns the normalized fingerprint, whether a registry record matches, registry status, any available registration date, model and media-type fields, certificate-validity status, registry-reported OpenTimestamps status, a verification URL when available, and explanatory assessments. Some result fields may be null, omitted, or unavailable. The response does not include the original artifact.

Purposes and data flow. Haawke uses the fingerprint to retrieve the corresponding existing public registry record and uses the connecting network address as a rate-limit key to help prevent abuse and maintain availability. The MCP service sends the fingerprint to the registry service in a read-only lookup URL. It does not forward the incoming request's authorization header, conversation context, or connecting address to the registry. The registry returns an existing public record, which may include declared attribution, file metadata and a thumbnail; the MCP service discards those additional fields and returns only the verification fields listed above to ChatGPT. A lookup does not register or modify a record. Haawke does not sell connector request or result data or use it for marketing, advertising, profiling, or model training.

Recipients. Cloudflare provides hosting and network services for the MCP endpoint and registry and may process request, network, operational, and security data to provide those services. The address seen by Haawke may be an OpenAI infrastructure address rather than the end user's address. OpenAI processes the user's ChatGPT conversation and the tool request and response under OpenAI's own terms and privacy practices. Haawke does not receive the user's full ChatGPT conversation through this tool.

Retention. Haawke's application handles the lookup in request memory and does not write individual verification requests or results to an application database. Production Workers Logs and Traces are disabled for the MCP and registry services, and no observability export destinations are configured. The MCP rate limiter has a 60-second enforcement window; this is not a promise that its underlying counter or related provider data is deleted after 60 seconds. Cloudflare's Workers metrics documentation states that aggregate Worker metrics can be inspected for up to three months. This queryable period is not a verified deletion deadline for all underlying data. Cloudflare's Rate Limiting API documentation describes locally cached counts and background synchronization but does not specify the underlying counter's deletion deadline. For provider-managed infrastructure and security information, Cloudflare's privacy policy describes purpose-based retention and legal obligations, without a single fixed period for these categories. We have not confirmed a service-specific maximum retention or deletion deadline for that data and cannot promise zero provider retention or deletion after 60 seconds. OpenAI's handling and retention of ChatGPT conversations are governed by OpenAI's policies.

Choices and requests. No Haawke account is required. You can choose not to submit a fingerprint or stop using the connector. For privacy questions or requests concerning data associated with a lookup, contact craig@haawke.com; we will assess the request under applicable law and the controls available to us. We have no verified control to locate or delete an individual request from provider-managed rate-limit, metrics, infrastructure, or security data. A lookup does not authorize deletion of an existing public provenance record or an external Bitcoin commitment.
